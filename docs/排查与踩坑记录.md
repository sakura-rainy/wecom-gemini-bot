# 排查与踩坑记录

这里整理了搭建与长期运行这套企业微信机器人过程中遇到的真实问题与解决方案，供同样部署在轻量 VPS 上的朋友参考。

---

## 坑 1：512 MB 内存 VPS 响应极慢（单条消息 3 分多钟）

- **现象**：发一条简单的「你好」，耗时 3 分钟以上才回复。
- **原因**：OpenCode CLI 运行时峰值内存占用常在 `250～450 MB` 左右；512 MB 内存的机器很容易把可用内存吃穿，导致频繁写入 Swap 产生磁盘 I/O 抖动。
- **解决**：
  - 将 VPS 升级到 **1 GB 内存**，并保留 **1 GB Swap**；
  - 升级后使用轻量 Flash 模型单条消息耗时稳定降到 **9 秒左右**。

---

## 坑 2：误切图像模型或免费额度为 0 的模型，导致整条队列卡死整整 2 小时

- **现象**：微信发任何消息，机器人都回 `消息已收到，将在当前任务完成后处理`，整整 2 小时后弹出 `agent session timed out (no response)` 和 `session reset`。
- **原因**：
  1. 误切到例如 `google/gemini-3.1-flash-image` 这类在 Free Tier 配额为 `0` 的模型后，Google API 会返回 `429 Quota exceeded ... limit: 0`；
  2. OpenCode 遇到该错误后会在后台不断退避重试且不输出事件；
  3. `cc-connect` 默认空闲超时 `idle_timeout_mins = 120`（2 小时），于是整条队列被死锁 2 小时。
- **解决**：
  - 在 `/root/.cc-connect/config.toml` 全局顶层加入：
    ```toml
    idle_timeout_mins = 5
    max_turn_time_mins = 15
    ```
  - 切模型只选可用文本模型（见下文新老 Key 差异）。

---

## 坑 3：改完 `config.toml` 的模型后，第一句话依然卡死在旧模型

- **现象**：明明已经把 `config.toml` 改回可用的文本模型，重启后发消息却依然触发旧模型报错。
- **原因（非常隐蔽）**：
  - 排查 OpenCode 本地日志与 `opencode.db` 后发现：如果当前活跃的旧会话历史消息较多、已经触发了上下文自动压缩（`agent=compaction`），OpenCode 在恢复该会话时，**会直接沿用待压缩历史父消息上记录的旧模型去跑 `compaction`，而忽略外部传入的新 `--model` 参数**。
- **解决**：
  - 在微信里直接发送 `/new` 开启一个新的干净会话（或者先停掉 `cc-connect` 服务，清理残留 `opencode run` 进程后切换/新建会话）。

---

## 坑 4：`/model switch` 带上了尖括号 `< >`

- **现象**：机器人提示 `用法: /model switch <序号> 或 /model switch <模型名>`，结果发送 `/model switch <28>` 后，机器人真的回复 `模型已切换为 <28>`，随后 OpenCode 报 `Model not found: <28>/.`。
- **原因**：`< >` 只是用法示例中的占位符，实际发送时不能带括号。
- **正确写法**：
  - 查看列表：`/model`
  - 按序号切换：`/model switch 21`（不要加 `< >`）
  - 按全名切换：`/model switch google/gemini-3.5-flash-lite`

---

## 坑 5：Google AI Studio 新老项目 Key 的模型差异与 `AQ.` 新格式

- **新老 Key 模型差异**：较早创建的项目 Key 可能仍可正常调用 `google/gemini-2.5-flash`；而新建项目的 Key（实测支持 `AQ.` 开头的新格式密钥）可能会对 `gemini-2.5-flash` 直接返回 `HTTP 404 (no longer available to new users)`，提示改用新版本模型。
- **Free Tier 实测可用性**：
  - 稳定快速日常模型：`google/gemini-3.5-flash-lite`、`google/gemini-flash-lite-latest`（约 8～10 秒返回，适合挂机）；
  - 较强推理模型：`google/gemini-4-hydrogen`（实测 Free Tier 可调用，但 OpenCode 每次带约 4 万+ token 上下文加上 `--thinking`，高峰期可能遇到 `HTTP 503 high demand` 重试，耗时在 11 秒到 1 分钟不等）；
  - Google 免费层级限额按**项目（Project）**共享，同一项目下建多个 Key 不会叠加免费额度。

## 坑 6：`systemd` 不会读取 `~/.bashrc` 里的 `GEMINI_API_KEY`

- **现象**：终端里手跑 `opencode` 正常，交给 `systemctl start cc-connect` 后却找不到 Key 或读取的是另一把旧 Key。
- **原因**：`systemd` 服务默认不会加载 `~/.bashrc`。
- **解决**：使用 `opencode` 自身的凭证文件 `~/.local/share/opencode/auth.json`（权限设为 `0600`），它不依赖 shell 初始化脚本；需要切换 Key 时直接改这里并同步更新 `~/.bashrc`（如果平时也手跑的话）。

---

## 坑 7：企业微信聊天气泡去繁就简与消除“斜体字”

- **隐藏英文思考气泡 & 底部状态栏**：
  在 `config.toml` 添加：
  ```toml
  [display]
  thinking_messages = false
  reply_footer = false
  ```
- **动作描写变成斜体字**：
  企业微信智能机器人支持 Markdown 渲染，如果在 `AGENTS.md` 里写了 `*(晃了晃尾巴)*`，星号会被渲染成歪斜的斜体字。
  将 `AGENTS.md` 中的动作描写统一改用纯中文括号 `（晃了晃尾巴）`，并禁止输出 `*`、`**`、`_`、`#`、`>` 等 Markdown 符号，同时发一次 `/new` 清除旧会话的格式惯性，回复就会全部端正显示为普通正体。
